Arquitectura del Sistema & Integridad Referencial

Proyecto de Bases de Datos • ESCOM IPN • Base de Datos seguros_db

1

Frontend Web (HTML/Tailwind/Alpine)

Captura de formularios con validación estricta en cliente (Regex RFC ^[A-Z&Ñ]{3,4}[0-9]{6}[A-Z0-9]{3}$, CP de 5 dígitos, teléfono a 10 dígitos).

2

Capa de Backend / API REST

Procesa las peticiones HTTP JSON, ejecuta transacciones ACID y mapea la jerarquía de herencia de vehículos (VEHICULO base con subtipos AUTOMOVIL y MOTOCICLETA).

3

PostgreSQL (Docker Compose port 5432)

Base de datos normalizada con restricciones ON DELETE RESTRICT / CASCADE, llaves foráneas diferibles y tipos numéricos de alta precisión para reclamaciones.

Reglas de Integridad Referencial Destacadas

  • CLIENTE a POLIZA: ON DELETE RESTRICT para proteger pólizas activas ante eliminaciones accidentales de clientes.
  • VEHICULO a AUTOMOVIL / MOTOCICLETA: Relación de supertipo/subtipo con integridad estricta de matrícula.
  • RECLAMACION a PAGO_RECLAMACION: Llave foránea compuesta (ID_ACCIDENTE, NUM_POLIZA, NUM_DE_PAGO) asegurando trazabilidad de pagos financieros.
